About {{ settings.app_name }}

A self-hosted chess.com analytics dashboard. Everything here is computed from your own game history and a local chess engine — no chess.com login, no data leaves the server.

Where the data comes from

Game history, ratings, and results come from the chess.com Published-Data API — a public, read-only, no-key API. We pull your monthly game archives one request at a time (chess.com asks clients to be polite), and because past months never change we fetch each one once and cache it forever in a local SQLite database. Only the current month is re-checked on each sync.

Puzzle and lesson stats come from chess.com's unofficial website endpoints (also no login). They're best-effort — if they ever change, those cards simply disappear and nothing else breaks.

The pipeline

  1. Sync — pull new games & rating snapshots into SQLite (daily, plus a "Sync now" button).
  2. Analyze — run every game through Stockfish and classify each of your moves.
  3. Aggregate — the charts and insights are live SQL queries over that stored data.

It all runs in a Docker container on a home server; the app is a Python (FastAPI) backend rendering these pages, with charts drawn client-side by a vendored copy of Chart.js.

How the Stockfish analysis works

Every stored game is replayed move-by-move through Stockfish (the strongest open-source chess engine), running inside the container at a "balanced" search depth of ~10 with the top two candidate moves considered. For each of your moves we ask the engine for its best move and compare:

  • If you played the engine's top move → Best (or Great/Brilliant, see below).
  • Otherwise we measure centipawn loss — how much worse your move was than the best, in hundredths of a pawn — and bucket it:
< 20 cpExcellent
20–49 cpGood
50–99 cpInaccuracy
100–299 cpMistake
≥ 300 cpBlunder

Average centipawn loss (ACPL) — the average of those losses across a game — is the number coaches actually track. Lower is better; a falling ACPL trend is the clearest sign you're genuinely improving. We also split it by phase (opening / middlegame / endgame) and record each game's eval swing so we can spot comebacks (won from ≥3 pawns down) and collapses (lost from ≥3 pawns up).

How this differs from chess.com

These labels are our approximation of chess.com's Game Review, not a copy of it. chess.com doesn't expose per-move analysis through any API, so we compute our own — and a few things differ on purpose:

  • We flag far more "Brilliant" moves (you currently have {{ brilliants }}, well above what chess.com's review would credit). Our "Brilliant" = you found the only strong move and it involved a material sacrifice. chess.com's definition is stricter and more secretive, so their count is lower. Take our brilliancies as "nice sacrifices you found," not as an official chess.com tally.
  • Our ratings chart uses rated games only and is built from your actual per-game ratings, so it can differ slightly from chess.com's graph.
  • Our streak is a game-day streak — chess.com's is higher because it also counts puzzle and lesson days.
  • Depth ~10 is shallower than chess.com's server-side review, so exact centipawn numbers won't match theirs move-for-move — but the trends (are you blundering less? improving your ACPL?) are what matter, and those are sound.
